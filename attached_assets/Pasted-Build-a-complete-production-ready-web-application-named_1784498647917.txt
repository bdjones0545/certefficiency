Build a complete, production-ready web application named **CertEfficiency** using the attached `design.md` file as the visual source of truth.

The application is a premium certification exam preparation platform centered entirely around a chat interface with an AI tutor named **Sarah**.

The landing page is the product.

Do not build a traditional marketing website. When users open CertEfficiency, they should immediately enter the Sarah chat experience.

Sarah will ultimately run on a private AI agent server connected through a Cloudflare Tunnel. I already have the tunnel credentials and will connect them after the application is built.

Until the real Sarah connection is configured, the entire platform must still be functional using a clearly isolated local development adapter with realistic mocked responses.

Do not directly integrate OpenAI, Anthropic, Claude, Gemini, or another hosted AI provider into the application.

All AI reasoning, question generation, study plans, document interpretation, tutoring, exam grading, and adaptive learning logic will eventually be managed by Sarah through the tunnel.

The frontend and backend should be designed so the mock Sarah adapter can later be replaced with the real tunnel integration without changing the user interface or core application architecture.

# Sarah Request Contract

Use a stable canonical request structure.

Each Sarah request should include relevant context without requiring Sarah to make unnecessary calls back to the application.

Example structure:

```json
{
  "requestId": "uuid",
  "eventType": "message.received",
  "user": {
    "id": "uuid"
  },
  "certification": {
    "id": "uuid",
    "name": "NSCA CSCS",
    "examDate": "2026-10-01"
  },
  "conversation": {
    "id": "uuid",
    "mode": "learn"
  },
  "message": {
    "id": "uuid",
    "content": "Explain periodization."
  },
  "context": {
    "recentMessages": [],
    "topicMastery": [],
    "recentAnswers": [],
    "studyPlan": null,
    "uploadedResources": []
  }
}
```

Every Sarah response must be normalized and validated before persistence.

Use this pipeline:

```text
bounded input
→ canonical schema
→ structured Sarah output
→ normalization
→ validation
→ transactional versioned persistence
→ guarded job completion
→ optional side effects
→ stable retrieval
```

Never directly trust an unvalidated Sarah response.
