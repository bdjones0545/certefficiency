## Canonical Sarah success response

Sarah returns synchronous JSON shaped like:

```json
{
  "message": {
    "type": "assistant",
    "content": "Sarah response text"
  },
  "actions": [],
  "metadata": {
    "correlationId": "uuid"
  }
}
```

The Replit adapter must read:

```text
response.message.content
```

Do not expect:

```text
response.content
response.data.content
response.assistantMessage
response.result.message
```

unless a deliberate normalization layer wraps the canonical response.

## Error response handling

If Sarah returns HTTP `200` but:

* `message.type === "error"`
* `metadata.degraded === true`
* the content is a structured fallback

persist the visible message instead of leaving the job pending.

Use the product’s intended distinction:

* usable fallback response → persist assistant message and mark completed, with degraded metadata
* genuine unrecoverable error → mark failed and expose a visible retryable error

Do not leave a job in `queued` or `processing` after any terminal Sarah response.

* connection failure

