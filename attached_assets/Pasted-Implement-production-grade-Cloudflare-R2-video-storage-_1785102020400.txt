Implement production-grade Cloudflare R2 video storage and secure streaming for the CertEfficiency AI Agent Course.

## Current infrastructure

Cloudflare R2 is already configured and working.

* R2 bucket: `aiagentcourse`
* Existing rclone remote: `certefficiency-r2`
* Lesson 3 has already been uploaded successfully
* Lesson 3 object key:

`courses/ai-agent-builder/lesson-3.mp4`

Do not attempt to upload or move the existing Lesson 3 file. Integrate the application with the object that is already stored in R2.

## Primary objective

Replace the current large-video upload and playback workflow with a reusable Cloudflare R2 architecture.

The application must:

1. Store private course videos in R2.
2. Store only the R2 object key in the database.
3. Verify authentication and course enrollment before playback.
4. Generate short-lived presigned playback URLs on the backend.
5. Stream the video directly from R2.
6. Support future lessons and future courses without duplicating logic.

Do not make the bucket public.


The endpoint should use this format:

```text
https://<ACCOUNT_ID>.r2.cloudflarestorage.com
```

Never expose these credentials through frontend environment variables, API responses, logs, error messages, or client bundles.

Validate the required variables during server startup and fail with a clear configuration error when they are missing.

## R2 storage service

Create a reusable server-side R2 storage service using the AWS SDK S3 client.

Use packages equivalent to:

```text
@aws-sdk/client-s3
@aws-sdk/s3-request-presigner
```

The service should provide typed methods such as:

```ts
getSignedPlaybackUrl(objectKey, expiresInSeconds)
objectExists(objectKey)
getObjectMetadata(objectKey)
deleteObject(objectKey)
```

Prepare the service so presigned upload support can be added later, but do not expose upload credentials to the browser.

Use:

* region: `auto`
* the Cloudflare R2 endpoint
* path-style behavior only if required by R2
* strict object-key validation

Reject object keys that:

* begin with `/`
* contain `..`
* contain backslashes
* reference another bucket
* use an unsupported course-media prefix

Course videos should use a predictable structure such as:

```text
courses/{course-slug}/{lesson-slug}.mp4
```

## Secure playback endpoint

Create an authenticated backend endpoint similar to:

```text
POST /api/courses/:courseId/lessons/:lessonId/playback
```

or follow the project’s existing API conventions.

The endpoint must:

1. Require an authenticated user.
2. Load the requested course and lesson.
3. Confirm that the lesson belongs to the requested course.
4. Confirm that the lesson has a valid `video_object_key`.
5. Verify that the user has access to the lesson.

Access should be granted only when one of the following is true:

* the lesson is explicitly marked as the free preview lesson
* the user has an active or valid enrollment
* the user has a completed Stripe purchase that grants course access
* the user has an authorized administrator role

Do not trust frontend state, route parameters, or a client-provided enrollment flag.

After authorization:

* generate a short-lived presigned GET URL
* default expiration: 15 minutes
* return only the minimum required playback information

Example response:

```json
{
  "playbackUrl": "short-lived-presigned-url",
  "expiresIn": 900
}
```

Do not return the R2 access key, secret, bucket credentials, or internal authorization details.

Use generic `403` or `404` responses where appropriate so unauthorized users cannot enumerate private lesson assets.

## Course-player integration

Update the existing AI Agent Course player to request a playback URL from the backend when the student opens a lesson.

The frontend must not construct R2 URLs itself.

Expected flow:

```text
Student opens lesson
→ frontend requests playback authorization
→ backend verifies user and enrollment
→ backend generates short-lived R2 URL
→ frontend loads the URL into the video player
→ R2 streams the video directly
```

Requirements:

* display a loading state while obtaining the URL
* display a useful retry state when playback authorization fails
* refresh the playback URL when it expires or when the player receives an expired-signature error
* avoid repeatedly generating URLs during normal rerenders
* clear the playback URL when switching lessons or signing out
* do not place presigned URLs in analytics events or application logs

Preserve the current Apple-style course experience.

## Security requirements

* Keep the R2 bucket private.
* Never expose R2 credentials to the browser.
* Never commit credentials to source control.
* Never persist presigned URLs.
* Require authorization before every playback URL is issued.
* Use short expiration periods.
* Validate lesson ownership and course enrollment server-side.
* Rate-limit playback URL generation.
* Add appropriate audit logging without logging the signed URL.
* Redact secrets from errors.
* Prevent object-key traversal.
* Do not allow arbitrary object keys from frontend requests.
* Derive the object key from the authorized lesson database record.
